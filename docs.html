Referencia para clientes

Conecta con la API de Ventas

Consulta el consolidado de ventas por sucursal y año, o registra una nueva venta mediante solicitudes HTTP.

Servidor localhttp://localhost:3000

El puerto predeterminado es 3000. Si el servidor usa la variable PORT o está desplegado en otro host, sustituye el origen de las URL de ejemplo.

Antes de empezar

Formato de las solicitudes

La API acepta JSON y no configura autenticación en las rutas documentadas.

Antes de consumir productos, aplica productos.sql sobre la base de datos indicada por DB_NAME; la tabla ya debe existir y el script crea los dos procedimientos almacenados requeridos.

Acceptapplication/json Content-TypeEnvía application/json en solicitudes con cuerpo. CodificaciónUTF-8

Lectura

Consultar productos

Devuelve todos los productos registrados con su categoría, precios y ubicación de pasillo, ordenados por identificador.

GET/api/v1/productos

Ejemplo de solicitud

curl "http://localhost:3000/api/v1/productos" \
  -H "Accept: application/json"

Respuesta · 200 OK

{
  "status": "success",
  "total_registros": 1,
  "data": [
    {
      "id_producto": 12,
      "id_categoria": 2,
      "nombre_producto": "Teclado",
      "precio_unitario": 45,
      "costo_proveedor": 30,
      "ubicacion_pasillo": "A-03"
    }
  ]
}

Escritura

Registrar producto

Crea un producto asociado a una categoría existente.

POST/api/v1/productos
CampoTipoRequeridoValidación
id_categoriaEnteroSíDebe corresponder a una categoría existente.
nombre_productoTextoSíEntre 1 y 100 caracteres.
precio_unitarioEnteroSíMayor o igual a cero.
costo_proveedorEnteroSíMayor o igual a cero.
ubicacion_pasilloTexto o nullNoHasta 10 caracteres; por defecto, null.

Ejemplo de solicitud

curl -X POST "http://localhost:3000/api/v1/productos" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{"id_categoria":2,"nombre_producto":"Teclado","precio_unitario":45,"costo_proveedor":30,"ubicacion_pasillo":"A-03"}'

Respuesta · 201 Created

{
  "status": "created",
  "data": {
    "id_producto": 12,
    "id_categoria": 2,
    "nombre_producto": "Teclado",
    "precio_unitario": 45,
    "costo_proveedor": 30,
    "ubicacion_pasillo": "A-03"
  }
}

La respuesta devuelve la fila insertada por el procedimiento almacenado. Si la categoría no existe, la API responde 400 Bad Request.

Lectura

Consultar consolidado

Devuelve las filas generadas por el procedimiento almacenado para la sucursal y el año indicados.

GET/api/v1/ventas/consolidado

Parámetros de consulta

NombreTipoRequeridoDescripción
sucursalTextoSíIdentificador o nombre de la sucursal esperado por la base de datos.
anioEnteroSíAño que se utilizará para consultar el consolidado.

Ejemplo de solicitud

curl "http://localhost:3000/api/v1/ventas/consolidado?sucursal=Centro&anio=2025" \
  -H "Accept: application/json"

Respuesta prevista · 200

{
  "status": "success",
  "total_registros": 0,
  "data": []
}

Las columnas de cada elemento de data dependen del resultado del procedimiento almacenado db_ventas_tech.

Incidencia en la implementación actual La ruta referencia row[0] en vez de rows[0] al construir la respuesta. Por eso, aunque la consulta llegue a la base de datos, actualmente puede responder 500 en lugar del 200 previsto.

Escritura

Registrar una venta

Crea una venta ejecutando el procedimiento almacenado db_registrar_venta.

POST/api/v1/ventas/

Campos del cuerpo JSON

NombreTipo recomendadoRequeridoDescripción
id_productoNúmero enteroSíIdentificador del producto.
id_clienteNúmero enteroSíIdentificador del cliente.
cantidadNúmeroSíCantidad vendida. Debe ser distinta de cero para superar la validación actual.
fecha_ventaCadenaSíFecha aceptada por la base de datos; se recomienda el formato YYYY-MM-DD.

Ejemplo de solicitud

curl -X POST "http://localhost:3000/api/v1/ventas" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{"id_producto":12,"id_cliente":34,"cantidad":2,"fecha_venta":"2025-04-18"}'

Respuesta · 201 Created

{
  "status": "created",
  "message": "Venta registrada exitosamente",
  "datos_registrados": {
    "id_producto": 12,
    "id_cliente": 34,
    "cantidad": 2,
    "fecha_venta": "2025-04-18"
  }
}

La ruta comprueba que los cuatro campos tengan valor, pero no valida por sí misma que los identificadores existan ni que la fecha sea válida.

Referencia

Errores y códigos de estado

200Consulta completada. Respuesta con status, total_registros y data (sujeta a la incidencia GET indicada arriba). 201Venta registrada correctamente. 400Faltan parámetros o campos obligatorios. 500Error interno o de base de datos.

Ejemplo · faltan parámetros del consolidado

{
  "error": "Bad request",
  "message": "debe enviar ambos parámetros"
}

Ejemplo · faltan campos al registrar

{
  "error": "bad request",
  "message": "todos los parámetros son obligatorios"
}

Los valores de error conservan las mayúsculas y minúsculas que devuelve cada ruta.
